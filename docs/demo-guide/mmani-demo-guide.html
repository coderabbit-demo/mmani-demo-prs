Internal · Do / Say / See runbook · CodeRabbit Field Engineering Enablement

Follow one finding: from Jira ticket to Deep Scan

A single feature, written by a coding agent, followed end to end: local review in the CLI and VS Code, the pull request review, Triage, Change Stack, QA Agent, the Security Deep Scan and Attack Surface, Fix with AI, and QA user journeys. The same two findings appear at every stop. Demo repository coderabbit-demo/mmani-demo-prs, PR #3, Jira story SC-10. Captured October 28, 2026, in light mode. Allow about 30 minutes plus questions.

Open with this "One Jira ticket, one coding agent, one branch. Let's follow two things the agent got wrong — a security hole and a money bug — from the developer's laptop all the way to the security team's scan. Same findings, every stop."

How to read this runbook

Take one stage at a time, top to bottom. Each step has three parts.

Appendix C — Local setup for the CLI and VS Code demos

Steps 3 and 4 review the coding agent's branch on your laptop. The branch must be checked out, and the review must compare it against the commit the agent started from — not main, which now holds the corrected reference implementation. Run every command from a terminal; nothing here pushes or changes the shared repository.

  • Git and GitHub access to coderabbit-demo/mmani-demo-prs (public).
  • CodeRabbit CLI installed (see docs.coderabbit.ai/cli) and VS Code with the CodeRabbit extension.
  • Signed in to the coderabbit-demo organization in both.

Appendix D — Live storefront repro (F2)

Exact steps to reproduce F2 by hand in the running app, if you want to show the defect live instead of (or alongside) the QA journey screenshots in Stage 7. The storefront must run the agent/discount-codes code — the same branch the CLI/VS Code review uses — so the bug is present. Data is synthetic and resets on every restart.

1. Start the app

cd ~/projects/mmani-demo-prs
git switch agent/discount-codes      # the buggy branch (see Appendix C)
npm run dev                          # catalog :4001, orders :4002, gateway :8080, storefront :5173

Open http://localhost:5173/. The /demo-ready skill starts this for you.

2. The negative-total repro (the headline)

  1. Add the Ceramic carrot mug ($15.00) to the cart — quantity 1.
  2. Open the cart and apply discount code SAVE20 (a $20.00 fixed code).
  3. Observe: Subtotal −$5.00, Discount −$20.00, Total −$25.00.

Why −$25.00: the $20 discount is subtracted twice — once as a quantity −1 adjustment line ($15 − $20 = −$5 subtotal), then again via discount_cents (another −$20) — and the fixed amount is never capped to the subtotal. Code: discounts.ts:67-73 (the two deductions) and :29-30 (no cap).

3. The double-count variant (positive but wrong)

  1. Build a cart totalling $65.00.
  2. Apply WELCOME10 (10%).
  3. Observe the net comes to $52.00 instead of the correct $58.50 — the 10% ($6.50) is deducted twice.

Seeded discount codes

  • SAVE20 — $20.00 fixed (use for the −$25.00 repro).
  • WELCOME10 — 10% off (use for the $65 → $52 double-count).
  • APPAREL15 — 15% off apparel only.
  • VIP50 — $50.00 fixed, single use.
  • SUMMER25 — 25% off, expired (shows the 422 "not active" path).

Reset

Restart npm run dev to clear the cart and re-seed. Stop the server with pkill -f scripts/dev.ts after the demo.
